# Справочник полей учебного датасета «Инциденты SOC + инференс ML-модели» (модуль 3, практика 3.6)

Учебный датасет практики **3.6 «Интеграция ML»** курса «Интеллектуальный
анализ и визуализация данных» (трек BI-аналитика). 

Комплект дополняет датасет модуля 1.5 (`iavd_incidents_raw_target`):
к карточкам инцидентов добавлен **лог инференса ML-модели** — как она
оценивала те же карточки в режиме советчика аналитика ИБ. Это позволяет анализировать качество работы модели на аналитическом дашборде.

## 1. Состав комплекта и связи

| Файл                                 | Строк  | Колонок | Содержимое                                                       | Ключ          |
| ------------------------------------ | ------ | ------- | ---------------------------------------------------------------- | ------------- |
| `iavd_incidents_raw3_target.parquet` | 16 443 | 39      | карточки инцидентов SOAR (алерты, сгруппированные в инцидент)    | `incident_id` |
| `MODEL_PREDICTIONS_target.parquet`   | 19 393 | 67      | лог инференса ML-модели (те же карточки + 28 полей предсказаний) | `incident_id` |
| `calendar.parquet`                   | 629    | 18      | справочник дат 2024-04-12…2025-11-20                             | `Дата`        |
| `dataframe.parquet` («Период»)       | 299    | 2       | метки скользящих окон 7/30/90/180 дней                           | `Дата`        |

Связи в модели данных приложения:

- **карточка ↔ инференс — 1:1** по `incident_id`; инференсов больше, чем
  карточек: у 2 950 инференсов карточки нет (в выборку карточек они
  не попали). В Qlik такие строки выпадают при выводе карточных полей
  (внутреннее соединение) — учитывайте это при подсчёте метрик;
- **инференс ↔ Календарь** — по полю `Дата` (календарные срезы и окна);
- **дата ↔ Период** — готовый фильтр «последние 7/30/90/180 дней».

ML-модель: единственная версия `wlarf-dec-jun-v3` (`model_version_id=1`),
порог классификации **0.82** (`model_params`) привязан к классу 0; в приложении Qlik
используется симметричный порог для класса 1 (`vThreshold = 1 − 0.82 = 0.18`).

## 4. Производные поля скрипта приложения

Этих полей НЕТ в parquet — скрипт приложения вычисляет их при загрузке
(принцип «считай один раз, используй много»):

| Поле | Формула | Зачем |
|---|---|---|
| confusion | по (y, y_pred): TN/FP/TP/FN; пусто для неразмеченных и исключённых (3 554 шт.) | клетка матрицы ошибок; FN — пропущенная атака |
| Flag_ValidLabel | 1, если y = 0/1 | включать в метрики качества только размеченные |
| Label_Status | Не размечено / Размечено / Исключено (Спам/Дубль) | человекочитаемый фильтр разметки |

Переменные приложения: `vThreshold = 0.18` (= 1 − 0.82 — симметричная
граница вероятности FP-класса), шкала Харрингтона `vRiskLimit_*`
(0.37 / 0.63 / 0.80 → НИЗКИЙ/СРЕДНИЙ/ВЫСОКИЙ/КРИТИЧЕСКИЙ) и цветовое
кодирование y/y_pred/confusion (палитра «Бриз»). Комментарии — в файле
`IAVD_Assesment_Script_v02_annotated.qvs`.

## 6. Мультизначные поля — JSON-массивы

Большинство технических полей хранит **JSON-массив строк**:
`["значение1", "значение2"]`. В отличие от датасета модуля 1.5, разделитель
`~~||~~` больше не используется. В части полей элементы — пары
«ключ\|значение»: `"узел\|src"`, `"учётка\|утилита"` (разделитель `д|`).

Правила разбора:

- **ML (pandas):** `import json;` затем `df['col'].apply(json.loads)` →
  списки; разворот в строки — `.explode()`; пары —
  `.str.split('|', n=1, expand=True)`; для текстовых признаков —
  объединение элементов через `'; '.join`. Пустые значения пропускайте
  (`json.loads('')` — ошибка).
- **BI (Qlik):** элементы JSON можно получить по позиции
  `SubField(SubField(value, '"', 2), '"', 1)` — но для длинных списков
  проще агрегировать текст или оставить поле как контекст в таблицах.
  Пары «ключ\|значение» — `SubField(pair, '|')`.

## 7. Предупреждения для студентов

1. **model_input**: часть значений (≈1 594 из 19 205) — **обрезанный JSON**
   (артефакт выгрузки инференса). Разбор — только в `try/except`, иначе
   упадёт вся обработка.
2. **risk_percent** — десятичный тип (decimal): в pandas приходит как
   `Decimal` — при необходимости явно приводите `float(x)`.
3. **Метрики считайте по Flag_ValidLabel = 1**: без фильтра в метрики
   попадут неразмеченные и исключённые карточки (в т.ч. 2 950 инференсов
   без карточки) — Precision/Recall будут искажены.
4. **Данные учебные**: значения условные, сценарии синтетические.
